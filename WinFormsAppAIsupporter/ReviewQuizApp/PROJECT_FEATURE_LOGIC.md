# 과제 복습 퀴즈 기능 및 로직 설명

## 1. 프로젝트 개요

이 프로젝트는 대학교 과제 데이터를 기반으로 AI가 복습 퀴즈를 생성하고, 사용자가 퀴즈를 풀고, 결과와 풀이 기록을 다시 조회할 수 있도록 만든 Windows Forms 기반 퀴즈 관리 프로그램이다.

퀴즈는 독립적으로 생성되는 것이 아니라 반드시 과제 JSON 데이터를 선행 입력으로 사용한다. 사용자는 과제, 생성 목적, 문제 유형, 문항 수, 난이도를 설정하고, 프로그램은 해당 조건을 AI API에 전달해 과제 내용에 종속된 퀴즈를 생성한다.

## 2. 사용자 관점의 기능 설명

### 2.1 시작 조건

프로그램을 정상적으로 사용하려면 두 가지 조건이 필요하다.

- AI API 키가 환경 변수에 설정되어 있어야 한다.
- `Data/assignments` 폴더에 과제 JSON 파일이 있어야 한다.

API 키가 없거나 과제 JSON 파일이 없으면 퀴즈 생성 기능은 잠기며, 화면에는 경고 메시지가 표시된다.

### 2.2 과제 선택

사용자는 설정 화면에서 과제 목록을 선택한다. 과제 목록은 `Data/assignments` 폴더에 있는 JSON 파일을 기준으로 자동 구성된다.

JSON 내부 구조는 고정되어 있지 않다. 프로그램은 JSON 파일 전체 내용을 읽어 AI에게 전달하고, AI가 해당 내용을 해석해 퀴즈를 생성한다.

### 2.3 생성 목적 설정

사용자는 직접 생성 목적을 입력할 수 있고, 미리 제공되는 대학교 과제 유형별 예시 형식도 선택할 수 있다.

현재 제공되는 생성 목적 형식은 다음과 같다.

- 보고서/레포트 핵심 이해
- 발표/프레젠테이션 점검
- 코딩/실습 과제 검토
- 중간/기말 시험 대비
- 토론/논술 과제 준비

예시 형식을 선택하면 생성 목적 입력칸에 기본 문장이 자동으로 들어간다. 사용자는 자동 입력된 문장을 그대로 사용할 수도 있고, 필요에 따라 수정할 수도 있다.

### 2.4 문제 조건 설정

사용자는 다음 조건을 설정할 수 있다.

- 문제 유형: O/X, 객관식, 주관식
- 문항 수: 1개부터 15개까지
- 난이도: 쉬움, 보통, 어려움

문제 유형은 여러 개를 동시에 선택할 수 있다.

### 2.5 AI 퀴즈 생성

`퀴즈 생성` 버튼을 누르면 프로그램은 선택된 과제 JSON, 생성 목적, 문제 유형, 문항 수, 난이도를 AI API에 전달한다.

AI는 다음 규칙을 따라 퀴즈를 생성한다.

- 생성 목적에서 다른 언어를 명시하지 않으면 모든 퀴즈 문구를 한국어로 작성한다.
- 모든 문제는 과제 JSON의 제목과 내용에만 근거해야 한다.
- 일반 배경지식, 추정, 외부 사실, 과제 JSON에 없는 내용으로 문제를 만들 수 없다.
- JSON에서 명확히 뒷받침되지 않는 개념은 문제, 정답, 선택지, 해설, 태그에 사용할 수 없다.
- O/X 문제는 선택지를 `O`, `X`로 구성한다.
- 객관식 문제는 가능한 경우 4개 이상의 선택지를 제공한다.
- 주관식 문제는 채점 가능한 짧은 정답을 제공한다.

생성된 퀴즈는 화면에 표시되며, 최신 생성 퀴즈 JSON도 `Data/generated-quiz-latest.json`에 저장된다.

### 2.6 퀴즈 풀이

퀴즈 화면에서는 한 문항씩 문제를 풀 수 있다.

- O/X와 객관식은 선택지 버튼으로 답을 선택한다.
- 주관식은 텍스트 입력칸에 답안을 입력한다.
- `정답 확인` 버튼을 누르면 현재 문항의 결과, 정답, 해설이 표시된다.
- `이전`, `다음` 버튼으로 문항을 이동할 수 있다.

### 2.7 결과 확인 및 기록 저장

사용자가 `제출` 버튼을 누르면 프로그램은 전체 문항의 정답 수와 점수를 계산한다.

제출 시 미응답 문항이 있으면 경고를 표시하고, 그래도 제출할지 확인한다. 제출이 완료되면 결과창이 표시되고, 결과창을 닫으면 자동으로 설정 화면으로 돌아간다.

결과 기록에는 다음 정보가 저장된다.

- 퀴즈 ID
- 퀴즈 제목
- 과제 ID
- 과제 제목
- 풀이 시간
- 정답 수
- 전체 문항 수
- 점수
- 각 문항별 사용자 답안
- 각 문항별 정답
- 정답/오답 여부

### 2.8 기록 조회 및 다시 풀기

사용자는 `기록 조회` 화면에서 이전에 푼 퀴즈 기록을 확인할 수 있다.

기록을 선택하면 해당 퀴즈의 문항별 결과가 표시된다.

- 풀이일
- 퀴즈명
- 과제명
- 점수
- 문항별 내 답
- 문항별 정답
- 문항별 정답/오답 여부

저장된 퀴즈 스냅샷 파일이 존재하면 `다시 풀기` 버튼으로 같은 퀴즈를 다시 풀 수 있다.

### 2.9 기록 삭제

기록 조회 화면에서는 기록 삭제 기능도 제공한다.

- `선택 삭제`: 선택한 퀴즈 기록 1개와 해당 기록에 연결된 퀴즈 스냅샷 파일을 삭제한다.
- `전체 삭제`: 모든 퀴즈 기록과 저장된 퀴즈 스냅샷을 삭제한다.

전체 삭제는 되돌릴 수 없기 때문에 확인 메시지를 띄운다.

## 3. 개발자 관점의 로직 설명

### 3.1 전체 구조

프로젝트는 WinForms 기반이며, 주요 책임은 다음과 같이 분리되어 있다.

- `Form1.cs`: 전체 화면 구성, 사용자 입력 처리, 페이지 전환, 퀴즈 풀이 흐름 제어
- `Forms/QuizResultForm.cs`: 제출 후 결과창 표시
- `Services/AssignmentRepository.cs`: 과제 JSON 파일 로드
- `Services/AssignmentQuizGenerator.cs`: AI 설정 확인 후 내부 생성기로 요청 위임
- `Services/InternalAiAssignmentQuizGenerator.cs`: AI API 호출, 프롬프트 구성, JSON 응답 파싱
- `Services/QuizDataLoader.cs`: 생성된 퀴즈 데이터 검증 및 정규화
- `Services/QuizHistoryService.cs`: 풀이 기록 저장, 조회, 삭제, 퀴즈 스냅샷 관리
- `Models`: 과제, 퀴즈, 문항, 결과 기록 데이터 모델 정의

### 3.2 데이터 흐름

기본 데이터 흐름은 다음 순서로 진행된다.

1. 프로그램 시작
2. API 키 환경 변수 확인
3. `Data/assignments` 폴더에서 과제 JSON 파일 로드
4. 사용자가 과제와 퀴즈 조건 입력
5. `QuizGenerationRequest` 객체 생성
6. AI 생성기 호출
7. AI 응답 JSON을 `QuizDataFile` 객체로 역직렬화
8. `QuizDataLoader`로 퀴즈 데이터 검증
9. 퀴즈 화면 렌더링
10. 사용자 답안 저장
11. 제출 시 점수 계산
12. 결과 기록과 퀴즈 스냅샷 저장

### 3.3 API 키 처리

API 키는 소스 코드에 직접 저장하지 않고 환경 변수에서 읽는다.

우선순위는 다음과 같다.

1. `GROQ_API_KEY`
2. `XAI_API_KEY`
3. `GEMINI_API_KEY`
4. `OPENAI_API_KEY`

단, `XAI_API_KEY` 값이 `gsk_`로 시작하면 GroqCloud 키로 판단해 Groq API로 처리한다.

API 키가 없으면 `AiProvider.None` 상태가 되며, 프로그램은 퀴즈 관련 기능을 비활성화한다.

### 3.4 과제 JSON 처리

과제 JSON은 `AssignmentRepository`에서 로드한다.

각 JSON 파일은 다음 방식으로 내부 객체가 된다.

- 파일명: 과제 ID 및 제목으로 사용
- 파일 경로: 과제 파일 위치로 저장
- 파일 전체 내용: AI에게 전달할 과제 본문으로 저장

JSON 구조를 특정 스키마로 강제하지 않는 이유는, 팀 프로젝트에서 과제 관리 시스템의 JSON 구조가 아직 확정되지 않았거나 과제 유형마다 달라질 수 있기 때문이다.

### 3.5 AI 프롬프트 제한

AI 프롬프트는 `InternalAiAssignmentQuizGenerator.BuildPrompt()`에서 생성된다.

프롬프트에는 다음 제한이 포함되어 있다.

- 생성 목적, 난이도, 문항 수, 허용 문제 유형을 명시한다.
- 별도 언어 지시가 없으면 한국어로 생성하도록 지시한다.
- 모든 문제는 과제 JSON에만 근거해야 한다.
- 외부 지식, 추정, JSON에 없는 사실을 금지한다.
- 문제, 정답, 선택지, 해설, 태그 모두 과제 JSON에 종속되도록 제한한다.
- 반환 형식은 지정된 JSON 스키마만 허용한다.

이 제한은 AI가 과제와 무관한 일반 상식 문제를 생성하지 않도록 하기 위한 핵심 안전장치이다.

### 3.6 AI 제공자별 처리

현재 구현은 여러 AI 제공자를 지원한다.

- OpenAI
- Gemini
- GroqCloud
- xAI

각 제공자는 서로 다른 API 형식을 사용하지만, 최종적으로는 동일한 `QuizDataFile` 구조의 JSON을 반환하도록 요청한다.

### 3.7 퀴즈 데이터 모델

퀴즈 전체는 `QuizDataFile`로 표현된다.

주요 필드는 다음과 같다.

- `QuizId`: 퀴즈 고유 ID
- `QuizTitle`: 퀴즈 제목
- `GeneratedAt`: 생성 시간
- `Questions`: 문항 목록

각 문항은 `QuizQuestion`으로 표현된다.

- `Id`: 문항 ID
- `Type`: 문제 유형
- `Title`: 문제 문장
- `Options`: 선택지 목록
- `CorrectAnswer`: 정답
- `Explanation`: 해설
- `Tags`: 태그

문제 유형은 `QuestionType` enum으로 관리한다.

- `TrueFalse`
- `MultipleChoice`
- `ShortAnswer`

### 3.8 퀴즈 검증 로직

AI가 반환한 JSON은 바로 사용하지 않고 `QuizDataLoader`에서 검증한다.

검증 목적은 다음과 같다.

- 문항이 비어 있지 않은지 확인
- 문항 ID가 중복되지 않는지 확인
- 문제 제목과 정답이 비어 있지 않은지 확인
- O/X 문제의 선택지와 정답 형식을 정규화
- 객관식과 O/X 문제에 선택지가 존재하는지 확인

### 3.9 화면 전환 로직

`Form1`은 하나의 폼 안에서 세 개의 페이지 패널을 전환한다.

- 설정 페이지
- 퀴즈 풀이 페이지
- 기록 조회 페이지

설정이 끝나고 퀴즈가 생성되면 퀴즈 풀이 페이지가 표시된다. 제출 후 결과창이 닫히면 자동으로 설정 페이지로 돌아간다.

### 3.10 답안 처리 및 채점

사용자의 답안은 `Dictionary<string, string>` 형태로 저장된다.

- key: 문항 ID
- value: 사용자 답안

객관식과 O/X는 선택된 라디오 버튼 값을 저장한다. 주관식은 텍스트 입력값을 저장한다.

채점은 `QuizDataLoader.SameAnswer()`를 사용해 사용자 답안과 정답을 비교한다. 제출 시 전체 문항을 순회하며 정답 수를 계산하고, 점수는 `CorrectCount * 100 / TotalCount` 방식으로 계산한다.

### 3.11 기록 저장 구조

퀴즈 결과 기록은 `QuizHistoryService`가 담당한다.

저장 위치는 다음과 같다.

- 풀이 기록: `Data/history/quiz-history.json`
- 생성 퀴즈 스냅샷: `Data/generated-quizzes/*.json`
- 최신 생성 퀴즈: `Data/generated-quiz-latest.json`

기록 조회 화면에서 다시 풀기를 수행하려면 저장된 퀴즈 스냅샷 파일이 필요하다.

개별 기록 삭제 시에는 히스토리 JSON에서 해당 기록을 제거하고, 해당 기록과 연결된 퀴즈 스냅샷 파일도 함께 삭제한다. 이때 삭제 대상 파일이 `Data/generated-quizzes` 폴더 내부에 있는지 확인해 다른 경로의 파일이 삭제되지 않도록 제한한다.

### 3.12 예외 처리 및 안정성

프로그램은 다음 상황에 대해 사용자에게 경고를 표시한다.

- API 키가 없는 경우
- 과제 JSON 파일이 없는 경우
- 문제 유형을 하나도 선택하지 않은 경우
- AI 퀴즈 생성에 실패한 경우
- 저장된 퀴즈 스냅샷을 불러오지 못한 경우
- 결과 기록 저장에 실패한 경우
- 미응답 문항이 있는 상태에서 제출하는 경우

## 4. 현재 구현 범위 요약

현재 프로젝트는 6번 역할인 `복습 퀴즈 모듈 & QA 엔지니어` 범위에 맞춰 구현되어 있다.

구현된 범위는 다음과 같다.

- 과제 JSON 기반 AI 퀴즈 생성
- 생성 목적 예시 형식 제공
- O/X, 객관식, 주관식 문제 풀이 UI
- AI API 키 검증
- 과제 데이터 존재 여부 검증
- AI 프롬프트 제한
- 한국어 기본 생성 규칙
- 과제 JSON 종속 생성 규칙
- 점수 계산
- 결과창 표시
- 풀이 기록 저장
- 기록 조회
- 다시 풀기
- 선택 기록 삭제
- 전체 기록 삭제
- 제출 후 설정 화면 자동 복귀

## 5. 이번 점검 및 리팩토링 내용

이번 전체 점검에서 다음 항목을 정리했다.

- 결과창 UI의 깨진 한국어 문구를 정상화했다.
- 결과창 점수 계산에 문항 수 0개 방어 로직을 추가했다.
- 히스토리 서비스의 깨진 오류 메시지를 정상화했다.
- 개별 기록 삭제 시 연결된 퀴즈 스냅샷 파일도 함께 삭제하도록 변경했다.
- 히스토리 저장 로직을 `SaveRecords` 메서드로 분리해 중복을 줄였다.
- 스냅샷 삭제 시 `Data/generated-quizzes` 폴더 내부 파일만 삭제하도록 경로 안전장치를 추가했다.

## 6. 향후 개선 가능 사항

추가 개발 시 고려할 수 있는 개선 사항은 다음과 같다.

- 기록 조회 화면에 날짜/과제명/점수 기준 필터 추가
- 주관식 채점 기준을 단순 문자열 비교에서 AI 기반 의미 비교로 확장
- 과제 JSON 미리보기 화면 추가
- 퀴즈 생성 전 예상 프롬프트 확인 기능 추가
- 퀴즈 결과를 CSV 또는 PDF로 내보내기
- 팀 프로젝트의 공통 데이터 매니저와 저장 경로 통합

## 7. 유지보수 원칙

프로젝트의 기능, 로직, 저장 구조, API 처리, UI 흐름이 변경될 경우 `PROJECT_FEATURE_LOGIC.md`도 함께 업데이트한다.

특히 다음 변경은 문서 갱신 대상이다.

- 사용자 화면 흐름 변경
- AI 프롬프트 규칙 변경
- API 키 또는 제공자 처리 방식 변경
- 과제 JSON 또는 퀴즈 JSON 저장 구조 변경
- 기록 저장, 조회, 삭제 로직 변경
- 예외 처리 및 경고 메시지 변경
