# MeetingMinutesApp 개발자 README

## 1. 프로젝트 개요

`MeetingMinutesApp`은 회의 녹음 파일을 기반으로 STT 원문을 생성하고, 사용자가 원문을 확인한 뒤 AI가 회의록 형식으로 정리하는 WinForms 모듈이다.

주요 입력은 오디오 파일이고, 주요 출력은 STT 원문, AI 회의록, Markdown/JSON 저장 파일이다. 팀 프로젝트에 통합할 때는 독립 폼 또는 회의록 기능 모듈로 연결할 수 있다.

## 2. 전체 처리 흐름

1. 사용자가 녹음 파일을 선택한다.
2. 회의 카테고리와 세부 주제를 선택한다.
3. 선택한 카테고리에 맞는 STT 힌트 용어를 구성한다.
4. `STT 변환`을 실행한다.
5. 변환된 STT 원문을 화면에 표시한다.
6. 사용자가 STT 원문을 확인하거나 수정한다.
7. `회의록 정리`를 실행한다.
8. AI가 회의 내용을 주제별 회의록으로 정리한다.
9. 결과를 Markdown, JSON, meta 파일로 저장한다.
10. `회의록 기록` 탭에서 저장된 회의록을 다시 조회한다.

## 3. 주요 클래스 역할

### `Form1.cs`

WinForms UI와 사용자 이벤트를 담당한다.

- 파일 선택
- STT 변환 버튼 처리
- 회의록 정리 버튼 처리
- 진행률 표시
- 취소 처리
- 회의록 저장
- 회의록 기록 조회
- 설정 UI 관리
- 회의 카테고리/세부 주제 선택

회의 카테고리와 용어의 기준 데이터는 `Data/meeting-category-terms.json`이다. `Form1.cs`에는 JSON 로딩 실패 시 앱이 최소 동작할 수 있는 `일반 회의` fallback만 둔다.

### `MeetingAiService.cs`

STT와 AI 회의록 정리의 핵심 로직을 담당한다.

- STT API 호출
- 로컬 Whisper fallback
- 긴 음성 파일 분할 처리 연동
- STT 결과 정규화
- AI 회의록 의견 추출
- 최종 회의록 병합
- API 리미트 재시도
- STT 캐시와 회의록 요약 캐시
- AI 출력 품질 보정

### `AiConfiguration.cs`

환경 변수 기반 설정 로딩을 담당한다.

- API 키 확인
- STT 공급자 선택
- STT 모델 설정
- AI 회의록 모델 설정
- 요청 대기 시간과 토큰 설정
- 타임아웃 설정

### `AudioChunkingService.cs`

오디오 처리와 ffmpeg 연동을 담당한다.

- ffmpeg 탐색
- ffmpeg 자동 준비
- 긴 녹음 파일 분할
- STT 전 음성 전처리
- 모노/16kHz 변환
- 음량 평준화

### `LocalWhisperTranscriptionService.cs`

API STT가 실패하거나 API 키가 없을 때 로컬 Whisper STT 처리를 담당한다.

### `MeetingStorageService.cs`

회의록 파일 저장과 조회를 담당한다.

- Markdown 생성
- JSON 생성
- meta 파일 생성
- 저장된 회의록 목록 조회
- 기록 파일 불러오기

## 4. STT 처리 로직

STT는 설정에 따라 Groq 또는 OpenAI API를 먼저 사용할 수 있다. API 키가 없거나 STT API 호출이 실패하면 로컬 Whisper로 fallback한다.

긴 녹음 파일은 ffmpeg를 사용해 여러 구간으로 분할한 뒤 순서대로 STT 처리한다. 각 구간 결과는 `[구간 1]`, `[구간 2]` 형식으로 합쳐진다.

STT 원문은 회의록 생성의 원자료이므로 의미를 추정해서 크게 바꾸지 않는다. 대신 사용자가 `STT 원문 확인` 탭에서 직접 확인하고 수정할 수 있다.

## 5. AI 회의록 정리 로직

회의록 정리는 원문 전체를 한 번에 요약하지 않는다. 긴 원문을 작은 구간으로 나눈 뒤, 각 구간에서 회의에 필요한 의견 단서를 추출하고 최종 회의록으로 병합한다.

추출 기준은 다음과 같다.

- 찬성 의견
- 반대 의견
- 추가할 내용
- 삭제/제외할 내용
- 수정할 내용
- 새로 제시된 주제
- 결정 사항
- 담당 업무
- 확인 필요

최종 회의록은 주제별 논의 정리 형식으로 생성된다. AI가 없는 내용을 만들어내지 않도록 프롬프트에서 입력에 포함된 내용만 사용하도록 제한한다.

AI 회의록 출력에는 한국어 문장을 한글로 작성하도록 지시한다. `詳細` 같은 중국어/일본어 한자 표현이 섞이는 경우를 막기 위해 AI 출력 단계에서 최소 보정도 수행한다. 이 보정은 STT 원문에는 적용하지 않는다.

## 6. 캐시와 성능 최적화

긴 회의록은 API 호출 횟수와 토큰 사용량이 많아질 수 있으므로 캐시를 사용한다.

### STT 캐시

같은 오디오 파일과 같은 STT 설정이면 이전 STT 결과를 재사용한다. 파일 경로, 파일 크기, 수정 시간, STT 공급자, STT 모델, 전처리 설정, 프롬프트 설정, 카테고리/용어 설정을 캐시 키에 반영한다.

### 회의록 요약 캐시

회의록 정리 결과는 두 단계로 캐시한다.

- 전체 STT 원문 기준 캐시
- 구간 텍스트 해시 기준 캐시

중간에 API 리미트나 오류가 발생해도 이미 처리된 구간은 저장된다. 이후 다시 실행하면 저장된 중간 결과부터 이어서 처리할 수 있다.

## 7. 저장 구조

회의록 저장 위치는 실행 폴더 기준 `Data/meetings`이다.

저장되는 파일은 다음과 같다.

- `.md`: 사람이 읽기 위한 Markdown 회의록
- `.json`: 프로그램에서 다시 읽기 위한 구조 데이터
- `.meta`: 기록 목록 표시용 메타데이터

캐시 저장 위치는 다음과 같다.

- `Data/stt-cache`
- `Data/summary-cache`
- `Data/summary-cache/chunks`

## 8. 설정 및 환경 변수

API 키는 소스코드나 프로젝트 내부 파일에 저장하지 않는다. 사용자 또는 시스템 환경 변수로 관리한다.

주요 환경 변수는 다음과 같다.

- `GROQ_API_KEY`: Groq Chat API 및 Groq STT 사용 시 필요
- `OPENAI_API_KEY`: OpenAI STT 사용 시 필요
- `STT_PROVIDER`: `groq` 또는 `openai`
- `STT_MODEL`: STT 모델명
- `STT_CHUNK_MINUTES`: 긴 녹음 분할 단위
- `STT_AUDIO_PREPROCESSING`: STT 전처리 사용 여부
- `STT_PROMPT_ENABLED`: STT 힌트 프롬프트 사용 여부
- `GROQ_CHAT_MODEL`: 회의록 정리 모델명
- `GROQ_CHAT_DELAY_SECONDS`: AI 요청 사이 대기 시간
- `GROQ_MAX_AUTO_RETRY_SECONDS`: 자동 재시도 최대 대기 시간
- `GROQ_PARTIAL_MAX_TOKENS`: 구간별 의견 추출 출력 상한
- `GROQ_FINAL_MAX_TOKENS`: 최종 회의록 출력 상한
- `GROQ_SUMMARY_CHUNK_SIZE`: 회의록 정리 입력 구간 크기
- `AI_HTTP_TIMEOUT_SECONDS`: AI/STT HTTP 요청 타임아웃
- `LOCAL_WHISPER_MODEL`: 로컬 Whisper 모델명

설정 탭에서는 현재 설정 상태를 확인하고 일부 환경 변수를 수정할 수 있다.

## 9. 오류 처리 정책

사용자가 작업 흐름을 잃지 않도록 오류 발생 시 가능한 중간 결과를 보존한다.

처리 대상 오류는 다음과 같다.

- API 키 없음
- STT API 실패
- 로컬 Whisper 실패
- ffmpeg 없음 또는 실행 실패
- `400 Bad Request`
- `429 Too Many Requests`
- 하루 토큰 한도 초과
- 저장 실패
- 사용자 취소

API 리미트가 발생하면 응답의 대기 시간을 읽어 자동 재시도한다. 하루 토큰 한도처럼 짧은 대기로 해결되지 않는 경우에는 중간 캐시를 남기고 사용자에게 재실행 방법을 안내한다.

## 11. 팀 프로젝트 통합 방법

현재 모듈은 독립 실행 가능한 WinForms 앱 형태이다. 팀 메인 앱에 붙일 경우 메인 폼에서 회의록 기능 버튼을 만들고 `MeetingMinutesApp`의 폼을 호출하는 방식으로 연결할 수 있다.

통합 시 필요한 조건은 다음과 같다.

- API 환경 변수 설정
- 실행 폴더의 `Data` 쓰기 권한
- ffmpeg 실행 가능 환경
- 로컬 Whisper fallback을 사용할 경우 로컬 실행 환경 확인

다른 파트와 강하게 결합되어 있지 않으므로, 히스토리 기능이나 메인 대시보드에서는 저장된 Markdown/JSON 파일을 읽는 방식으로 느슨하게 연동할 수 있다.

## 12. 현재 한계와 주의사항

- STT 품질은 녹음 음질, 배경 소음, 발음, 전문용어에 크게 영향을 받는다.
- 긴 회의는 Groq/OpenAI API 리미트나 하루 토큰 한도에 걸릴 수 있다.
- AI 회의록은 STT 원문 오류를 완전히 복구하지 못한다.
- 로컬 Whisper는 사용자 PC 성능에 따라 처리 시간이 달라진다.
- ffmpeg가 필요하며, 실행 환경에 따라 자동 준비 또는 실행이 실패할 수 있다.
- AI 회의록 정리는 `GROQ_API_KEY`가 있어야 사용할 수 있다.
- `bin`과 `obj`는 빌드 산출물이다. 저장된 회의록과 캐시는 `Data` 아래에 생성될 수 있으므로 정리할 때 사용자 결과 파일을 함께 삭제하지 않도록 주의한다.
